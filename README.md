# Content Agents

Команда ИИ-агентов для контент-продакшна под Instagram и Telegram, с обязательным согласованием
человеком. Готовы этапы 0–2: каркас, ядро (статусы, очередь, бюджеты, LLM-клиент) и первый сквозной
сценарий в Telegram: бриф → план → утверждение → тексты Copywriter с проверкой Critic → правка с комментарием →
новая версия → утверждение → экспорт. Этап 2.5 (шаг 1): веб-панель — те же решения, что в Telegram, плюс
карточки агентов, доска задач, карточка запуска и расходы. Остальные агенты — следующие этапы (см. [CLAUDE.md](CLAUDE.md)).

## Что нужно

- Windows 11 + [Docker Desktop](https://www.docker.com/products/docker-desktop/) (WSL2) — или Linux/macOS с Docker
- Node.js 22 LTS (≥ 22.12)
- pnpm: один раз выполнить `corepack enable` (в PowerShell от администратора), версия pnpm возьмётся из `package.json`

## Установка

```powershell
git clone <repo-url> content-agents
cd content-agents
pnpm install
copy .env.example .env      # в bash: cp .env.example .env
```

Откройте `.env` и заполните пустые значения:

- `POSTGRES_PASSWORD` — любой надёжный пароль;
- `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` — любые строки (это логин/пароль локального хранилища,
  docker compose создаст такого пользователя).

`.env` в git не попадает.

## Запуск

```powershell
pnpm infra:up       # Postgres + хранилище; ждёт, пока оба станут healthy
pnpm db:migrate     # применить миграции
pnpm dev:api        # API на http://127.0.0.1:3000 (нужен PANEL_PASSWORD_HASH, см. раздел про панель)
```

## Проверка, что всё живо

```powershell
curl.exe http://127.0.0.1:3000/health    # в bash: curl ...
# {"status":"ok","checks":{"db":"ok","storage":"ok"}}   -> HTTP 200
```

Если какая-то зависимость недоступна, ответ будет `HTTP 503` и `"fail"` напротив неё; причина — в логе API.

Полная проверка (то же, что в CI):

```powershell
pnpm lint
pnpm typecheck
pnpm test                 # unit-тесты, без Docker
pnpm test:integration     # нужен pnpm infra:up
pnpm build
```

## Проверка этапа 2 на Windows, шаг за шагом

Команды — в PowerShell, в папке проекта.

**1. Обновить код и зависимости**

```powershell
git pull
pnpm install
pnpm infra:up
pnpm db:migrate
```

**2. Заполнить `.env`** (открыть в блокноте: `notepad .env`). Если `.env` ещё нет — `copy .env.example .env`.
Новые переменные этапа 2 (скопируйте строки из `.env.example`, если их нет в вашем `.env`):

| Переменная           | Что вписать                                                             |
| -------------------- | ----------------------------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather (`/newbot`)                                         |
| `TELEGRAM_OWNER_ID`  | ваш числовой Telegram id (напишите боту @userinfobot — он пришлёт `Id`) |
| `ANTHROPIC_API_KEY`  | ключ из console.anthropic.com                                           |
| `LLM_PROVIDER`       | сначала `mock`, на шаге 5 — `anthropic`                                 |

Ключи никому не пересылайте; `.env` в git не попадает.

**3. Бесплатный прогон в mock-режиме** (`LLM_PROVIDER=mock`, API не вызывается, $0):

```powershell
pnpm dev:bot
```

В Telegram придёт «✅ Бот запущен. LLM: mock». Дальше:

1. напишите боту бриф, например: «Подготовь пост для Instagram и пост для Telegram про осеннее меню кофейни»;
2. придёт план с расходами и сроками → нажмите **✏️ Изменить**, напишите комментарий → придёт план v2;
3. нажмите **✅ Утвердить** → придёт пакет: по каждому тексту 3 варианта и вердикт Critic;
4. у одного текста нажмите **✏️ Правка с комментарием**, напишите, что поправить → придёт версия 2 с пометкой
   «Ваш комментарий учтён»;
5. утвердите тексты (✅ 1/2/3 — выбрать вариант, ✅ все — утвердить все варианты) → придёт «Готово» с файлом
   `package.md`; папка с пакетом — `data\exports\…`.

Проверка белого списка: напишите боту с другого аккаунта — он не ответит.
Остановить бота: `Ctrl+C`.

**4. Первый реальный вызов API с жёстким лимитом $0.02**

```powershell
pnpm smoke:llm
```

Скрипт делает один маленький запрос к Claude и печатает ответ, токены и **ACTUAL COST** — фактическую
стоимость по данным API. Если бы вызов мог выйти за $0.02, он бы не был отправлен вовсе.

**5. Сценарий на реальной модели**: в `.env` поставьте `LLM_PROVIDER=anthropic`, перезапустите `pnpm dev:bot`
и повторите шаг 3. В плане бот покажет ожидаемую и максимальную стоимость; лимит задачи — $2
(`BUDGET_TASK_USD`). `/tasks` покажет статусы и потраченное по каждой задаче.

Если что-то пошло не так — в окне `pnpm dev:bot` будут строки с `"level":"error"` и причиной.

## Подключение Token Harbor (бесплатная модель), Windows, шаг за шагом

Команды — в PowerShell, в папке проекта.

**1. Обновить код и базу**

```powershell
git pull
pnpm install
pnpm infra:up
pnpm db:migrate
```

`db:migrate` должен вывести `applied: 0003_wallet_reconciliation` (или `up to date`).

**2. Поправить `.env`** — `notepad .env`.

Удалите строку `MODEL_PRICING_FILE=config/model-pricing.json`, если она есть (иначе бесплатная модель будет
считаться по ценам Anthropic как неизвестная — по максимальной ставке). Затем впишите/замените:

```
LLM_PROVIDER=tokenharbor
TOKENHARBOR_API_KEY=ваш_ключ
TOKENHARBOR_BASE_URL=https://tokenharbor.ai
TOKENHARBOR_AUTH=x-api-key
LLM_MODEL_CEO=claude-haiku-5.5:free
LLM_MODEL_CRITIC=claude-haiku-5.5:free
LLM_MODEL_WORKER=claude-haiku-5.5:free
LLM_MODEL_CLASSIFIER=claude-haiku-5.5:free
LLM_STRUCTURED_OUTPUTS=false
LLM_RATE_LIMIT_PER_MINUTE=60
LLM_RATE_LIMIT_PER_HOUR=1800
LLM_COST_SAFETY_FACTOR=1.2
```

Ключ никому не отправляйте. Модель для любой роли меняется только здесь, код трогать не нужно.

**3. Проверочный вызов шлюза**

```powershell
pnpm smoke:llm
```

Ожидаемо: `Provider: tokenharbor (https://tokenharbor.ai, auth x-api-key)`, `Model: claude-haiku-5.5:free`, два ответа
(`Request 1`, `Request 2`) с фразой-приветствием и строкой
`priced as claude-haiku-5.5:free (requested); served by claude-haiku-5.5; ... cost $0.000000` (шлюз отвечает именем
без `:free` — это нормально, цена берётся по модели из запроса), блок `Usage as reported by the provider` с токенами и
сырым `usage` от шлюза, строка `Second request: cache_read_input_tokens = …`, строка про кэш и
`ACTUAL COST ... $0.000000`.

- Строка `Prompt cache: NOT confirmed` — значит, шлюз не вернул `cache_read_input_tokens`; кэш считаем
  неподтверждённым (это не ошибка).
- `MODEL NOT LISTED` в строке `Price list` — модель не в `config/model-pricing.tokenharbor.json`, см. шаг 2.
- `401`/`403` — проверьте ключ и `TOKENHARBOR_AUTH` (можно попробовать `bearer`).
- `404` — проверьте, что `TOKENHARBOR_BASE_URL` без `/v1`.

**4. Бот на шлюзе**

```powershell
pnpm dev:bot
```

В приветствии должно быть: `LLM: Token Harbor (шлюз)`, `Адрес шлюза: tokenharbor.ai`, модели по всем ролям
`claude-haiku-5.5:free`, `Structured outputs: нет`, `Лимит запросов: 60/мин, 1800/час`,
`Бесплатные модели: claude-haiku-5.5:free`. Строки `⚠️ Нет цены` быть не должно.

Дальше — тот же сценарий, что в разделе этапа 2: бриф → план → утвердить → тексты → правка → новая версия →
утвердить. `/tasks` покажет $0 по задачам.

**5. Сверка с кошельком (на будущее, для платных моделей)**

Посмотрите баланс в личном кабинете Token Harbor и отправьте боту `/reconcile 12.34` — первая сверка сохранит
базу; следующие покажут, сходится ли наш учёт с фактическим списанием, и подскажут новый `LLM_COST_SAFETY_FACTOR`,
если шлюз списал больше.

**Вернуться на mock или прямой Anthropic** — поменять `LLM_PROVIDER` в `.env` и перезапустить бота.

## Веб-панель (этап 2.5, шаг 1): проверка на Windows, шаг за шагом

Команды — в PowerShell, в папке проекта. Понадобятся **три окна PowerShell** (бот, API, панель).

**1. Обновить код и базу**

```powershell
git pull
pnpm install
pnpm infra:up
pnpm db:migrate
```

`db:migrate` должен вывести `applied: 0004_panel_and_invocations` (или `up to date`).

**2. Пароль панели**

```powershell
pnpm panel:password
```

Введите пароль (не меньше 8 символов; при вводе символы не видны — это нормально) и повторите его.
Команда напечатает строку вида `PANEL_PASSWORD_HASH=scrypt:32768:8:1:...`. Откройте `.env` (`notepad .env`)
и вставьте эту строку целиком (если строка `PANEL_PASSWORD_HASH=` уже есть — замените её). Сам пароль нигде не
хранится, в `.env` лежит только хэш. Поменять пароль — снова `pnpm panel:password` и заменить строку.

Необязательные настройки (значения по умолчанию подходят): `PANEL_SESSION_IDLE_MINUTES=30` — выход после 30 минут
бездействия, `PANEL_SESSION_MAX_HOURS=12` — сессия живёт не дольше 12 часов, `PANEL_LOGIN_MAX_ATTEMPTS=5` и
`PANEL_LOGIN_LOCK_MINUTES=5` — после 5 неверных паролей подряд вход блокируется на 5 минут.

**3. Запуск** — каждая команда в своём окне:

```powershell
pnpm dev:bot     # окно 1: Telegram-бот + воркер, который выполняет работу агентов
pnpm dev:api     # окно 2: API панели на http://127.0.0.1:3000
pnpm dev:web     # окно 3: панель на http://127.0.0.1:5173
```

Важно: без `pnpm dev:bot` панель создаёт задачи, но агенты их не выполняют (воркер живёт в процессе бота).

**4. Войти.** Откройте в браузере **http://127.0.0.1:5173** (именно `127.0.0.1`, не `localhost`), введите пароль.
Неверный пароль покажет «Осталось попыток: N».

На главной — три карточки: **CEO, Копирайтер, Critic** со статусом, текущей задачей, последним запуском,
успешностью, расходом за сегодня, моделью (с пометкой «из .env») и версией промпта. Кнопки «Пауза», «Тест»,
«Настроить» и «Остановить всё» пока неактивны — это шаг 2. Вверху справа — активный провайдер и модели
(наведите мышь — подсказка со всеми ролями).

**5. Сценарий «бриф из панели → план → утвердить → пакет → утвердить»**

1. **+ Задача** → впишите бриф, например «Подготовь пост для Instagram и пост для Telegram про осеннее меню
   кофейни» → **Создать**. Откроется страница задачи; в Telegram придёт «🖥 В панели создана задача…».
2. Через несколько секунд на странице появится **План v1** (обновлять страницу не нужно). Тот же план придёт в
   Telegram с кнопками. В шапке у «Согласование» появится счётчик.
3. Нажмите **✅ Утвердить план** (на странице задачи или в разделе «Согласование»). В Telegram придёт
   «🖥 В панели: План утверждён…».
4. Появится блок **Тексты**: по каждому тексту 3 варианта и вердикт Critic. Пакет придёт и в Telegram.
5. Нажмите **✅ Утвердить всё оставшееся** (или ✅ 1/2/3 у каждого текста). Статус станет «экспортировано»,
   в Telegram придёт файл `package.md`, папка — `data\exports\…`.

**6. Решение из панели видно в Telegram и наоборот**

- Панель → Telegram: каждое решение в панели приходит в Telegram сообщением «🖥 В панели: …».
  Если после этого нажать старую кнопку в Telegram, бот ответит, что решение уже принято, — двойного решения не будет.
- Telegram → панель: создайте ещё одну задачу (можно прямо в Telegram), утвердите план **кнопкой в Telegram** —
  в панели статус и история обновятся в течение 3 секунд, в «Истории» будет «вы (Telegram)».

**7. Отклонение пакета и возврат**

На следующей задаче, когда придёт пакет, нажмите **✖️ Отклонить пакет** → появится подтверждение (можно написать
причину) → **Да, отклонить**. Статус — «отклонено», появится кнопка **↩️ Вернуть на согласование**; нажмите — пакет
снова ждёт решения. То же самое есть в Telegram: «✖️ Отклонить пакет» → «Да, отклонить» → «↩️ Вернуть на
согласование». После экспорта вернуть уже нельзя — кнопки нет.

**8. Остальные экраны**: «Задачи» — доска по колонкам; в задаче ссылка «Запуск» открывает карточку запуска
(версия промпта, модель, токены, кэш, стоимость, время); «Расходы» — сутки и месяц относительно лимитов, по агентам,
задачи на паузе по бюджету с кнопками +$1/+$5. **Выйти** — кнопка справа вверху.

**Собранная панель без Vite** (необязательно): `pnpm build`, затем `pnpm start:api` — панель откроется на
http://127.0.0.1:3000.

Если что-то не так: ошибки API — в окне `pnpm dev:api` (строки с `"level":"error"`); если API не стартует и
пишет `PANEL_PASSWORD_HASH: is required` — вернитесь к шагу 2.

## Демо ядра (этап 1)

```powershell
pnpm infra:up
pnpm demo:core
```

Демо создаёт временную базу, проводит задачу через гейт плана (агент сам утвердить не может), запускает
агента через очередь с фейковой моделью (первый ответ не проходит схему и чинится), показывает защиту от
дублей, паузу по бюджету, audit-лог, вызовы LLM и расходы. Реальных запросов к API нет, денег не тратит.

## Бюджет

По умолчанию: $5 в сутки, $50 в месяц, $2 на задачу (`BUDGET_*` в `.env`). На 80% придёт предупреждение.
Перед каждым платным вызовом система резервирует его максимальную стоимость; если вызов может выйти за
лимит, задача встаёт на паузу и спрашивает вас. Продолжение — только после вашего подтверждения.
Цены моделей лежат в `config/model-pricing.json`.

## Миграции

```powershell
pnpm db:status            # что применено
pnpm db:rollback          # откатить последнюю миграцию (--steps N — несколько)
pnpm db:migrate           # применить снова
```

Новая миграция: поменять `packages/db/src/schema.ts` → `pnpm db:generate` → рядом с созданным
`NNNN_name.sql` написать `NNNN_name.down.sql`.

## Режимы безопасности (по умолчанию)

| Переменная        | По умолчанию | Смысл                                                                          |
| ----------------- | ------------ | ------------------------------------------------------------------------------ |
| `PROVIDERS_MODE`  | `mock`       | Никаких внешних вызовов; `real` пока не реализован и падает с понятной ошибкой |
| `DRY_RUN`         | `true`       | Ничего не уходит наружу                                                        |
| `PUBLISH_ENABLED` | `false`      | Публикации нет (только экспорт); `true` запрещено при `DRY_RUN=true`           |

Если обязательная переменная не задана, приложение не стартует и пишет, какая именно:

```
Invalid configuration. Fix these environment variables (see .env.example):
  - POSTGRES_PASSWORD: is required (PostgreSQL password, same value docker compose uses)
```

## Остановка

```powershell
pnpm infra:down                 # данные сохраняются в docker volumes
docker compose down -v          # снести вместе с данными
```

## Частые проблемы

- **Порт 5432 или 8333 занят** — поменяйте `POSTGRES_PORT` / `S3_PORT` (и `S3_ENDPOINT`) в `.env`.
- **`password authentication failed`** после смены `POSTGRES_PASSWORD` — Postgres запоминает пароль при первом
  создании тома. Либо верните старый, либо `docker compose down -v` (удалит данные).
